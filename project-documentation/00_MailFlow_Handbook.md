# MailFlow Development Guidelines

## Purpose

This document defines the development standards and implementation rules for MailFlow.

All contributors and AI coding assistants must read this document before making any changes.

The documents inside this folder are the single source of truth for the project.

## Project

Project Name: MailFlow

## Source of Truth

Before making any changes, refer to these documents:

- PRD
- Technical Architecture
- Frontend Specification
- Security & Access Control
- Feature Ticket List

## Development Rules

1. Never implement features outside the Feature Ticket List unless explicitly requested.
2. Follow the Technical Architecture for backend design.
3. Follow the Frontend Specification for UI/UX.
4. Do not redesign existing pages unless instructed.
5. Keep the existing folder structure.
6. Reuse existing components whenever possible.
7. Maintain consistent naming conventions.
8. Write clean, modular, and production-ready code.
9. Do not remove existing functionality without approval.
10. Keep the codebase scalable and maintainable.

## Coding Standards

- Use TypeScript.
- Use Tailwind CSS.
- Follow React best practices.
- Use reusable components.
- Avoid duplicated code.

## Design Rules

- Modern SaaS UI.
- Dark theme.
- Clean typography.
- Minimal animations.
- Responsive layout.

## Before Completing Any Task

Verify:
- PRD compliance
- Feature Ticket alignment
- No architecture violations
- No unnecessary code
